# 포장 생성 시 아이템 최소 1개 정책 검토

> 면접 활용 상태: 과거 아이디어를 보존한 문서이며, 해결·검증된 면접 사례가 아니다. 현재 정책 검토와 구현 진행은 Bundle Task에서 다룬다.

> 기록 성격: 설계 아이디어. 아래 제안의 구현·실험 결과는 기록되어 있지 않다.
> 현재 적용 확인: 2026-09-14. 아래 빈 포장 허용 결론은 현재 생성 정책으로 적용하지 않는다.

## 현재 적용 여부

- **당시 고민:** 임시 저장을 지원하려면 빈 포장이 필요할 수 있다는 검토였다.
- **현재 결정과 이유:** [Policy Baseline](../../20_Deliverables/06_Policy_Baseline.md)의
  `INV-006`은 현재 등록 UI가 물품 최소 1개를 요구하므로 백엔드도 빈 포장 생성을
  허용하지 않기로 확정했다. 기존 정책의 현재 적용 상태를 연결한 것이며 새 합의가 아니다.
- **제외·재검토:** 임시 저장·자동 정리의 필요성과 상태 모델은 현재 확정하지 않는다.
  실제 임시 저장 요구가 생기면 별도 Task에서 검토한다.
- **검증 상태:** 생성 정책의 백엔드 검증은 아직 완료되지 않았다. OpenAPI 배열 제약은
  Bundle 생성 Task에서 `INV-006`과 일치하는지 확인한다.

## 당시 기록 — 원문 보존

- 번들은 빈 번들을 막기 위해 아이템이 최소 1개는 있어야 한다고 생각함
	- 일정시간 지나면 자동삭제하거나 임시 상태로 관리하는게 실무적
- 중간저장을 도입하려면 아이템 0개 허용이 실무적
- 결론: 번들 생성시 아이템 0개 허용하고, 등록완료 시점에 아이템 최소 1개인지 검증하자.
