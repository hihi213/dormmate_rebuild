# 폴더 구조 선택 기록

> 면접 활용 상태: 기존 선택 근거를 보존한 설계 메모다. 실제 문제 발생과 개선 결과를 확인한 기록이 없으므로 검증된 문제 해결 사례로 사용하지 않는다.

> 기록 성격: 설계 결정 과정. 확장성·탐색성에 대한 판단 근거이며 성능 측정 결과가 아니다.
> 현재 적용 확인: 2026-09-14. 도메인 중심·내부 Flat 원칙은 유지한다.
> 현재 기준은 [Tech Decisions의 폴더 구조 결정](../../20_Deliverables/04_Tech_Decisions.md#4-폴더-구조-결정-도메인-중심-flat)을 따른다.
> 아래 예시는 모든 빈 클래스를 먼저 생성하라는 작업 지시가 아니다.

## 결론
유지보수성과 확장성을 고려해 **도메인 중심** 구조를 선택한다.

## 왜 이 구조인가? (결정 흐름)
1. **모듈 확장성**: 냉장고 외에 세탁/도서관/다목적실 모듈이 늘어날 예정  
2. **탐색 속도**: 기능 단위로 코드가 모이면 찾기/수정이 빠름  
3. **경계 명확화**: 모듈 간 의존이 눈에 보이고, 결합도 관리가 쉬움  
4. **개인 유지보수**: 혼자 관리할 때 레이어(Controller/Service/Repo)보다 “기능”이 더 자연스럽게 떠오름
